# 2-bit experts on vLLM v0.24.0

**Status: frozen.** This line builds and is kept buildable; it is not developed. Fixes are merged when
they arrive as pull requests against the fork branch `moet-v0.24.0` of
[`kacper-daftcode/vllm-tmp`](https://github.com/kacper-daftcode/vllm-tmp) — the patch below is generated
from that branch and is never edited by hand ([CONTRIBUTING.md](../CONTRIBUTING.md)). Issues on this
line are closed as *not planned* unless they come with a fork-branch fix.

A generated patch on official vLLM v0.24.0 ([`patch/`](../patch/), image
[`Dockerfile.sm120-v024`](../Dockerfile.sm120-v024)) serves checkpoints the hardware cannot hold:
GLM-5.2 (753B) on two RTX PRO 6000 at 28–32 tok/s (128K window) and on four at 105 tok/s,
DeepSeek-V4-Flash (159B) on one RTX 5090 at ~31 tok/s (32K) and on one RTX PRO 6000 at 161 tok/s,
Kimi-K2.7-Code (1T) on four RTX PRO 6000 at 51 tok/s (256K).

- **2-bit experts at FP4 quality.** The routed experts go to a sign-symmetric 2-bit codebook on
  hand-written SASS kernels ([`kernels/`](../kernels/MANIFEST.md); naive 2-bit fails through sign
  asymmetry, not error size); a delta cache and a confidence gate bring FP4 back where it matters.
- **Experts beyond VRAM.** The 2-bit base can live in host RAM or NVMe pack files with the GPU as an
  expert cache; a miss is fetched and the step's graph replayed, bit-identical to a resident forward.
- **Against official v0.24.0.** The release cannot serve these models on SM120 as shipped: the patch
  moves the DeepGEMM and FlashInfer pins, gates the cluster-launch top-k off, fixes the `o_proj` scale
  layout, captures CUDA graphs in thread-local error mode, and adds MTP under pipeline parallelism and
  an NVFP4 KV cache. With the `VLLM_MOE_W2*` knobs off, the SM120 fixes are the only change.

Hooks, knobs and the SM120 fixes in detail: [v024-port.md](v024-port.md). Quality method:
[quality.md](quality.md). Kimi-K2.7-Code specifics: [kimi-k27-code.md](kimi-k27-code.md).

## Build and serve

```bash
DOCKER_BUILDKIT=1 docker build -f Dockerfile.sm120-v024 -t vllm-moet-sm120:v024 .
DOCKER_BUILDKIT=1 docker build -f Dockerfile.recipes -t vllm-moet-recipes:v024 .
docker run --rm --gpus all --network host --ipc host --shm-size 64g -v /srv/models:/models \
  -e HF_TOKEN=... vllm-moet-recipes:v024 glm-5.2-nvfp4/pro6000x4-tp4-mtp   # --list: all recipes
```

The recipes image serves each benchmarked configuration (`bench/recipes/<model>/<config>.yaml`); the
benchmark process behind the tables is [`bench/README.md`](../bench/README.md). To apply the patch to
a vLLM checkout instead of using the image: [v024-port.md](v024-port.md), "Apply".
