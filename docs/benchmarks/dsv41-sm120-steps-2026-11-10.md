## Step 49 — the idle freeze

Measured in serving processes on the second host (`-r28` as built; one server lifetime of 96 fresh-prefill
and 6 decode requests; `gc.get_objects` by type between requests and the collector's own callbacks in
every process), and on the reference host from outside the container (per-thread scheduler statistics and
page-fault counts).

What accumulates after the start-up freeze, and what a full collection costs then (the switch off):

| what | number |
|---|---|
| a fresh 19K + 163K prefill pair, per worker | 1 450–1 600 objects |
| the same pair, in the EngineCore | ≈ 1 450 per pair |
| a full collection | 0.13–0.36 µs per object of this kind |
| a worker's first full collection | none for its first 23 pairs |
| after that | one every 1.3 pairs — 10–19 ms each 24–34 pairs after the start |
| a full collection with a worker's whole heap un-frozen | 550–600 ms; the 8 192-token step it falls into takes 763 instead of 238 ms, the other ranks wait in the collectives |

The reference host, nine hours and 160 M prompt tokens after a start (the switch off):

| what | number |
|---|---|
| one launch thread of one rank stops | for 0.3–0.4 s every 5–8 minutes of load per rank |
| fresh 163K prefills that contain such a pause | 8 of 23 (+160 … +360 ms, +82 ms on the mean) |
| run-to-run sd of the fresh 163K prefill | 1.9 % with them, 0.7 % without |
| the pause grows with the requests served | 288 → 404 ms in 2.7 hours of benchmark traffic; a restart resets it |

With the switch on:

| what | on | number |
|---|---|---|
| a full collection after an idle freeze | CPU test | 58 → 0.0 ms after the idle freeze, 1.3 ms for the next burst's 60 K objects |
| 12 pairs with 4 s between them: every worker and the EngineCore freeze once per gap | the second host, the same server lifetime | 1.5–2.1 ms per freeze, no full collection inside a request, a forced one afterwards 0.01 ms |
| 6 pairs back to back (no idle second) | the same | full collections of 1.3 → 3.0 ms inside requests, growing until the next idle second |
| fresh 163K, with the switch against without it at the same age: the medians of the 12 pairs with gaps / of the 6 pairs back to back, against the median of the 20 pairs before the switch in that lifetime — not two servers | the same | 5 174 / 5 178 ms against 5 188; every 8 192-token step regular |
| fresh 19K, the same comparison | the same | 659 / 656 against 654 |
| un-freezing a worker after 13 idle freezes and collecting its 1.32 M objects (one worker probed, not all six processes) | the same | no dead object found |
| resident memory per pair and worker | the same | grows by the same 0.15–0.22 MB with and without the switch |
| the API server's freezes, which fall inside long requests | the same | ≈ 1 ms, off the request's path; its resident memory stayed flat over them |
